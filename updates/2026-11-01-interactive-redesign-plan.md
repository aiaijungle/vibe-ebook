# AI 바이블 1~5권 개편 기획안 — 쉽게 · 깊게 · 재밌게 · 전문적으로 · 직접 해보게

2026-11-01 · 1차 시범(권별 인터랙티브 실습 1개씩) 적용 완료. 이 문서는 전권 확대 계획이다.

## 1. 왜 바꾸나

지금 책의 가치는 저자가 직접 만들고 실패한 기록에 있다. 문제는 그 경험이 **읽는 글**로만 전달된다는 점이다. 독자는 "그렇구나"에서 멈추고, 자기 업무에 옮기는 순간 막힌다. 개편의 목표는 한 문장이다.

> **각 장을 다 읽으면, 독자가 자기 업무로 결과물 하나를 직접 만들어 본 상태가 된다.**

## 2. 다섯 가지 원칙

| 원칙 | 지금 | 바꾼 뒤 |
|---|---|---|
| **쉽게** | 전문 용어·내부 용어가 설명 없이 등장, 한 문단에 여러 개념 | 장마다 "한 줄 요약 → 쉬운 설명 → 접어 둔 심화"의 3층 구조. 처음 나오는 용어는 그 자리에서 한 줄 풀이 |
| **깊게** | "이렇게 하라"는 지시 위주 | "왜 그런가"와 "언제 안 통하나"를 함께. 실패 사례는 원인 → 증상 → 복구 → 재발 방지 순서로 |
| **재밌게** | 성공담·과장 문구로 흥미 유도 | 독자가 직접 맞히고 틀리는 재미. 실제 사고 사례를 퀴즈·시뮬레이션으로 |
| **전문적으로** | 출처 없는 수치, 낡은 모델·가격 | 수치마다 출처와 기준일. 바뀌는 정보(모델·가격·명령어)는 본문에서 분리해 한곳에서 갱신 |
| **직접 해보게** | 코드·프롬프트를 읽고 복사 | 브라우저 안에서 바로 해보는 실습. 로그인·API 키·저장·전송 없음 |

## 3. 장 표준 틀 (모든 장에 적용)

1. **이 장에서 만들 것** — 결과물 하나와 걸리는 시간
2. **한 줄 요약** — 바쁜 독자는 여기서 핵심을 가져간다
3. **쉬운 설명** — 비유 하나, 그림 또는 흐름 하나
4. **직접 해보기** — 인터랙티브 실습 (3~5분)
5. **한 단계 깊게** (접기) — 원리, 예외, 다른 방법과의 비교
6. **저자의 실제 기록** (접기) — 날짜·상황·실수·복구. 지금 책의 강점을 여기에 모은다
7. **실무 노트** (접기) — 체크리스트, 팀 적용법, 법·보안 주의
8. **완료 확인** — 세 가지 질문에 "예"면 다음 장으로

이번 시범 실습 5개가 이 틀의 4~7번을 이미 따른다.

## 4. 인터랙티브 실습 유형

`assets/interactive-labs-20261101.js` 하나로 동작한다. 실습 내용은 HTML 안의 데이터만 바꾸면 늘어난다.

| 유형 | 하는 일 | 상태 | 맞는 주제 |
|---|---|---|---|
| **오류 찾기** (spot) | AI 초안에서 원문과 다른 문장 고르기 | ✅ 구현 | 사실 확인, 코드 리뷰, 번역 검수 |
| **판단 시뮬레이터** (choice) | 상황별로 첫 행동을 고르고 바로 이유 확인 | ✅ 구현 | 에러 대응, 보안 사고, 고객 응대 |
| **지시서 조립기** (builder) | 칸을 채우면 지시서 완성 + 빠진 요소 알림 | ✅ 구현 | 프롬프트, CLAUDE.md, 업무 인계표 |
| **분류하기** (sort) | 항목을 단계·종류로 나누고 정답과 비교 | ✅ 구현 | 권한, 승인, 모델 선택, 우선순위 |
| 순서 맞추기 | 작업 단계를 올바른 순서로 배열 | 2차 | 배포 절차, 장애 복구 |
| 비용 계산기 | 호출 수·길이·모델을 넣으면 월 비용 추정 | 2차 (가격 출처 확정 후) | 3·5권 비용 장 |
| 따라 하는 터미널 | 명령을 입력하면 미리 정한 결과를 보여 주는 가짜 터미널 | 3차 | 2·4권 설치·첫 실행 |
| 진행 기록 | 장별 완료 표시를 이 기기에만 저장 | 3차 | 전권 |

## 5. 권별 개편안

### 1권 AI 마케팅 자동화 입문 — "검수된 홍보글 하나"
- **대표 결과물:** 원문 → AI 초안 → 사실 확인표 → 게시 가능한 글
- **고칠 점:** "봇이 다 한다" 서사를 "사람이 검수하는 반자동"으로 통일. 블로그·유튜브 장을 같은 사례 하나로 연결
- **실습:** ✅ 홍보글 오류 찾기 / 지시서 조립기(원문·대상·금지 표현) / 채널별 길이 맞추기 판단

### 2권 바이브 코딩 실전 바이블 — "작은 도구 하나를 만들고 고치기"
- **대표 결과물:** 내 업무용 작은 웹 도구 1개 + 실수 기록 파일
- **고칠 점:** 장 번호 정리(현재 20장 → 부록 → 19장 → 21장 순). **필수 경로(설치 → 첫 도구 → 에러 → 배포)**와 **선택 부록(판매·RAG·에이전트·보안)**으로 분리. 72일 일지는 "저자의 실제 기록" 접기로 각 장에 나눠 배치
- **실습:** ✅ 에러 응급처치 / 따라 하는 터미널(설치) / 덮어쓰기 vs 범위 지정 비교 / 배포 전 점검 순서 맞추기

### 3권 AI 에이전트 바이블 — "실패해도 멈추고 넘겨주는 에이전트"
- **대표 결과물:** 승인 단계·호출 한도·재시도 규칙이 있는 에이전트 설계서
- **고칠 점:** 단계 구성은 유지. 첫 장의 시장 수치·연봉 이야기를 줄이고 "단일 호출로 안 되는 순간"부터 시작. 가격표는 기준일과 공식 링크로 대체
- **실습:** ✅ 자동/승인/사람 분류 / ReAct 한 바퀴 따라가기(생각·행동·관찰 고르기) / 기억 방식 고르기 / 비용 계산기

### 4권 Claude Code 바이블 — "검증까지 끝난 수정 한 건"
- **대표 결과물:** 작업 지시서 → 계획 → 수정 → 테스트 결과가 남은 커밋 1개
- **고칠 점:** 모델 표·명령어 목록을 본문에서 분리해 "현재 기준" 상자 하나로. 실수 12가지는 판단 시뮬레이터로 전환
- **실습:** ✅ 작업 지시서 조립기 / 실수 12가지 시뮬레이터 / 훅 이벤트 고르기 / CLAUDE.md 조립기

### 5권 AI에게 일시키는 비법 — "우리 팀 운영판 첫 페이지"
- **대표 결과물:** 업무별 담당자·권한 단계·한도·승인자·기록 위치가 적힌 운영판
- **고칠 점:** 내부 용어('시황', '강.12', 'silent_activator' 등)는 첫 등장 때 한 줄 풀이. 메모체("표면: … 본질: …")를 완결된 문장으로. 기업 사례는 출처 있는 것만 남겨 압축
- **실습:** ✅ L0~L4 권한 배치 / 결정 로그 조립기 / 자동화 사고 시뮬레이터(새벽에 멈춘 봇) / 회의록 → 할 일 오류 찾기

## 6. 진행 순서

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| **1차 (완료)** | 실습 엔진 + 권별 시범 실습 1개, 무료 구역 배치 | 5권 모두 모바일·데스크톱 동작, 오류 0 |
| 2차 | 권별 실습 3~4개로 확대, 해당 장 바로 옆에 배치 / 4권 모델표·3권 가격표 갱신 | 권마다 "대표 결과물"까지 실습으로 도달 가능 |
| 3차 | 2권 장 구조 재편, 5권 용어 풀이, 장 표준 틀 적용 | 모든 장에 한 줄 요약·완료 확인 존재 |
| 4차 | 영문판·일본어판 반영, 진행 기록 기능 | 언어별 같은 실습 동작 |

## 7. 잘 됐는지 보는 법

- 실습 완료율(실습을 끝까지 누른 비율) — 수집하려면 개인정보 없는 집계 방식을 별도로 정해야 함
- 독자 후기에서 "만들었다"는 결과물 언급 비율
- 무료 실습 → 구매 안내 클릭 비율
- 문의 중 "어디서 막혔다" 유형의 감소

## 8. 결정이 필요한 것

1. 2차 실습을 **무료 구역**에 둘지, **유료 본문 안**에 둘지 (지금 시범 5개는 무료 구역)
2. 2권을 실제로 두 권(필수 / 선택 부록)으로 나눌지, 한 권 안에서 경로만 나눌지
3. 실습 완료 집계를 할지 (한다면 저장 방식과 고지 문구)
