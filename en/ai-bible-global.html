A suggested order: 1 → 2 → 4 → 3 → 5

First learn to review an AI draft. Then define a small tool and verify its changes with Claude Code before connecting agent roles. Finish by deciding how a team will operate the workflow. This is a learning route, not a requirement to buy every volume.

Choose a shorter route

  • Content creator: Volume 1, then the source-of-truth and review decisions in Volume 5.
  • Builder: Volumes 2 and 4, then Volume 3 when one well-defined workflow is working.
  • Manager: Volume 5 first. Use Volume 1 to try a small task and bring in Volumes 2–4 when implementation requires them.

Try the method before buying

The free draft-review exercise includes a fictional input, a deliberately flawed draft and an answer key. Complete it without a password. You can then open a companion introduction and decide whether the corresponding full reader suits your next task.

A practical reading rhythm

  1. Define: Write one business question and decide what a good answer looks like.
  2. Make: Work with approved or fictional input and create a draft, tool or proposal.
  3. Check: Compare the result with its source and try a missing, conflicting or duplicate input.
  4. Record: Keep the changes, actual checks, unresolved questions and next action.

Run a small, inspectable lab

The public English lab guide explains the files and local commands. Download the lab files together so the code, sample data and tests use the same revision.

python ontology_lab.py
python -m unittest -v test_ontology_lab.py

The default fictional example should return ready_for_review with executed: false. Record your actual output and test summary. If Python cannot start, report the installation issue instead of marking the exercise complete.

The lab does not connect to an AI provider or production system. A passing local check does not verify a live booking service's authorization, payments or concurrent writes.

How to know you have learned something

  • Repeat it: another person can use the same input and understand the result.
  • Challenge it: a missing fact stays unknown; a conflicting fact prompts a review rather than an invented answer.
  • Account for effort: include setup, review and correction time, along with any tool cost.
  • Hand it over: record the source version, completed checks, remaining questions and next owner.

If you needed help, note where and why. Finishing with a clear unresolved question is more useful than reporting an unverified success.
