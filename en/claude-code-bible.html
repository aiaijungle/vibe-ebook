Why Order Matters

Mistake #1 when first using Claude Code: telling it to "fix bugs" right away. Then Claude patches the code without even examining it, guessing. It fails. Fix it again. It gets worse.

This happened during early AntiGravity AGI development. I told Claude Code to "optimize the data pipeline," but it patched the code without properly understanding it. It even touched unrelated files and broke a working module. Took 1 hour to recover.

After that, I never run quick fixes. Always explore first.

The 4-Step Golden Workflow

The Correct Claude Code Workflow
1
Explore — Understand (Don't touch code)
Read related files, understand the structure, and have Claude explain the current state. In this step, Claude must not modify any files.
2
Plan — Verify Plan (I must approve before next step)
Ask "which files will you change and how?" Claude explains the plan, and I review before giving the go-ahead.
3
Code — Implement (Validate immediately after each change)
Modify files according to plan. After each major change, test or run to verify immediately.
4
Commit — Complete (Claude does git commit)
After confirming tests pass, git commit. Claude writes the commit message in Conventional Commits format.

Python — Agent SDK Sequential Pipeline Pattern (Diagnosis → Improvement)
import anthropic

client = anthropic.Anthropic()

# Sequential pipeline: pass diagnosis results to the next agent
def run_pipeline(task: str):
    # Agent 1: Code review (Haiku — fast and cheap)
    review = client.messages.create(
        model="claude-haiku-4-5-20251001",
        max_tokens=1024,
        system="Code review expert. Find only bugs and security vulnerabilities.",
        messages=[{"role": "user", "content": task}]
    )

    # Agent 2: Receive review results and write improvement plan (Sonnet)
    solution = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=2048,
        system="Improvement plan expert. Provide specific code.",
        messages=[
            {"role": "user", "content": task},
            {"role": "assistant", "content": review.content[0].text},
            {"role": "user", "content": "Based on the above review, write improved code"}
        ]
    )
    return solution.content[0].text

            model="claude-haiku-4-5-20251001", max_tokens=512,
            messages=[{"role": "user", "content": t}]
        )
        return r.content[0].text
    return await asyncio.gather(*[call(t) for t in tasks])

🪟 Part F — Windows-Specific Tips

Most Claude Code tutorials are Mac/Linux-focused. When working on Windows, you hit unexpected blockers. If you're a domestic user, you absolutely need to know these.

⚠️ Common Windows Blockers
Path separators — Windows uses \, Linux·Mac use /. Use Path() in Python for automatic handling.
Korean encoding — If terminal is CP949, Korean text breaks. After opening PowerShell:
$OutputEncoding = [Console]::OutputEncoding = [System.Text.Encoding]::UTF8
Line breaks — Windows uses CRLF, Linux uses LF. When git diff looks odd, fix with .gitattributes.
Windows PowerShell — Essential setup before running claude
# Prevent Korean text corruption
$OutputEncoding = [Console]::OutputEncoding = [System.Text.Encoding]::UTF8

# Check Node.js version (v18+ required)
node --version

# Run Claude Code

*.json text eol=lf

Python execution — If python doesn't work, try py or python3.
