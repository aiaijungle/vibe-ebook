# 옵시디언 볼트 사용법

[[00 Dashboard|← 대시보드로]]

## 여는 법

1. Obsidian 앱 실행 → "Open folder as vault" → 이 저장소(`vibe-ebook`) 루트 폴더 선택
2. 저장소에 커밋된 `.obsidian/app.json`, `core-plugins.json`, `templates.json` 덕분에 파일탐색기·검색·백링크·템플릿 폴더가 별도 설정 없이 바로 세팅됨
3. 좌측 파일탐색기에서 `00-Vault/`가 숫자 접두어 덕분에 맨 위에 고정됨 — 실제 사이트 HTML(32개)과 시각적으로 분리되어 있음

## 이 볼트가 하는 일 / 하지 않는 일

- **한다**: 책 구조, 가격, 톤 원칙, 마케팅 페이지 현황을 서로 링크된 노트로 정리 → 기획·검수·인수인계용 지식 베이스
- **하지 않는다**: HTML을 자동 생성하지 않음. 실제 사이트에 반영하려면 여전히 해당 `.html` 파일(`book1.html`, `agent-bible.html` 등)을 직접 수정해야 한다. 노트를 고쳤다고 사이트가 바뀌지 않는다.

수정 작업 흐름: [[수정 로그]] 템플릿에 변경 내용 기록 → 실제 `.html` 파일 수정 → git 커밋. 노트와 실제 사이트 문구가 어긋나지 않도록, 가격/카피를 바꿀 때는 관련 책 노트([[00 Dashboard]]의 표에서 링크)도 같이 갱신한다.

## 선택 설치: 커뮤니티 플러그인 (기본 상태로도 전부 동작하니 필수는 아님)

- **Dataview** — [[00 Dashboard]]의 정적 표를 `01-Books/` 폴더의 frontmatter(`price`, `status`)를 읽는 라이브 쿼리로 바꿀 수 있음
- **Templater** — [[수정 로그]], [[신규 랜딩페이지 기획]] 템플릿에 날짜·변수 자동 채우기 추가
- **Obsidian Git** — 이 저장소가 이미 GitHub에 있으니 플러그인에서 remote를 그대로 잡으면 됨. 커밋 메시지 컨벤션은 기존 `git log`처럼 한국어로 간결하게(예: "6권 톤 교정: ..."). **자동 push는 끄고 수동으로 확인 후 push** 하는 걸 권장 — 노트북 등 다른 환경에서 동시에 같은 브랜치를 작업 중이면 push 충돌이 날 수 있음(순수 git 레벨 이슈, 옵시디언 자체 문제 아님).

## 브랜치/동시 작업 주의

옵시디언은 파일을 로컬에서 편집만 할 뿐 git 동작을 하지 않는다. 문제가 생길 수 있는 유일한 경우는 **같은 브랜치를 두 군데(예: 다른 컴퓨터의 클로드코드 세션)에서 동시에 커밋·푸시할 때**다. 이땐 push 전에 `git pull --rebase`로 먼저 최신 상태를 받아온다.
