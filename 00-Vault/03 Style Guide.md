# Style Guide — 톤 & 원칙

## 제독의 3대 서약 (책 시작 전 맹세)

**제1 계명**: 나는 내 손으로 직접 코드를 타이핑하지 않을 것이다.
(코드를 치는 노동은 AI의 몫이다. 나는 비즈니스 로직을 설계하고 명령만 내리는 지휘관이다.)

**제2 계명**: 나는 빨간 에러 화면을 두려워하거나 피하지 않을 것이다.
(에러는 컴퓨터가 고장 난 것이 아니다. 시스템이 나에게 보내는 가장 완벽한 진단서다.)

**제3 계명**: 나는 완벽한 기획보다, 조악하더라도 '오늘 당장 구동되는' 코드를 숭배할 것이다.

## 5단계 공식 (책의 전체 지도)

1. **베이스캠프 구축** — 폴더 고립화 + 도구 설치 + MCP 무장 (2~3장)
2. **감정 프롬프팅** — 비즈니스 목적을 감정으로 AI에 주입 (1장·8장)
3. **에러 멱살잡기** — 에러 로그를 손대지 말고 AI에 던지기 (5장)
4. **파이프라인 자동화** — 기록 시스템 + 무인 봇 공장 가동 (6장·11장)
5. **MRR 수익화** — 랜딩페이지 → RAG납품 → 과금 자동화 (12장)

## 톤 원칙 (커밋 히스토리에서 관찰된 규칙)

실제 `git log`에 반복적으로 등장하는 편집 패턴. 새 카피를 쓰거나 기존 문구를 다듬을 때 이 기준으로 자가 검수한다.

- **자랑 톤은 반복되면 트림한다.** 같은 자랑 포인트("30개 AI" 같은 숫자 자랑)가 문단마다 3연속 나오면 하나로 줄인다.
- **겸손을 유지한다.** 저자 소개에서 과장된 성취 나열보다 "참고 프레임"으로 톤을 낮춘다. 예: "교육은 아내 몫, AI는 참고" — 저자가 모든 걸 다 했다는 인상을 피한다.
- **사교육 반감을 완화한다.** 교육 관련 카피는 학원·사교육을 깎아내리는 대신 공감을 강화하는 방향으로 쓴다.
- **CTA 개수를 제한한다.** 한 페이지/챕터에 같은 CTA(예: 유튜브 채널 홍보)가 여러 번 반복되지 않게 한다. 실제 사례: "AI사냥꾼 CTA 7곳 → 2곳"으로 트림.
- **철학적 문장은 짧게, 체크리스트는 실행 가능하게.** 코엘료풍 철학 문장은 도입부에 한 번, 이후는 체크박스형 진단으로 전환.
- **가격 표기는 법적 안전 기준을 지킨다.** 프로모션 문구("100% 환불 보장")는 실제 환불 정책과 모순되면 제거한다. 전자상거래법 시행령 제21조 기준 "단순 변심 환불 불가"는 항상 명시.
