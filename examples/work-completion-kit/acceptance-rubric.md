# 업무 묶음 인수 기준 — 근거로 결정하기

이 기준은 워크북과 생성된 다섯 문서를 **사람이 인수 검토할 때** 사용합니다. 문서가 길거나 자동 검사에 통과했다는 이유로 합격시키지 않습니다. 생성 도구는 입력 누락과 일부 일관성을 확인할 수 있지만 원문의 진실성·검토자 신원·실제 실행·법적 적합성을 보증하지 않습니다.

최종 표시는 `ready_for_review`(문서 검토 준비), 보완 후 재검토, 또는 보류입니다. 문서 준비와 제품 배포 승인은 구분합니다. 실제 앱·발송·예약이 범위에 추가되면 아래 원래 기준을 그대로 재사용하지 말고 해당 통합 검증과 운영 승인 항목을 추가하세요.

English summary: this rubric assesses an evidence package, not a live system. `ready_for_review` means the package is ready for a human reviewer. Critical evidence gaps cannot be offset by a high average score. Mark an item “not applicable” only with a scope-based reason; “not run” is not a pass.

## 판정 방법

각 행에 검토자의 판정과 증거 위치를 적습니다.

- **충족:** 실제 문서·기록으로 요구사항을 확인할 수 있음.
- **보완:** 범위 안의 증거가 빠지거나 맞지 않음. 담당자와 기한 지정.
- **해당 없음:** 이번 범위에서 필요하지 않은 이유를 기록. 예: 문안 교정 과제의 셸 종료코드.
- **미실행:** 필요한 검사를 하지 않음. 통과 수에 넣지 않음.

평균 점수로 중요 실패를 덮지 않습니다. 특히 원문 없는 사실, 실제와 다른 실행 주장, 권한 없는 승인, 확인되지 않은 외부 결과의 재실행은 하나만 있어도 해당 결과물의 사용 판단을 보류합니다.

| 번호 | 인수 항목 | 확인할 증거 | 부족할 때 다음 행동 |
|---|---|---|---|
| A1 | 업무·범위·완료 단위가 구체적이다 | 과제 카드, 실제 산출물 위치 | 작업 하나로 줄이고 담당자 확정 |
| A2 | 원본의 권위·버전·시점을 설명한다 | source ID·owner·checked_at·validity | 정본 책임자 확인, 충돌 사실 보류 |
| A3 | 문안의 사실과 다음 행동이 원문과 같다 | 원문·초안·수정본·문장 대조표 | 잘못된 문장 수정 후 관련 채널 재검토 |
| B1 | 누락과 확인된 불가를 구분한다 | 정상·누락·0/불충족 사례 | 상태 규칙과 사용자 안내를 함께 수정 |
| B2 | 충돌·만료의 다음 행동이 있다 | 상태표, 확인 담당자 | 실패를 단순 오류 문구로 끝내지 않기 |
| B3 | 예상·실제·검사 방식이 분리되어 있다 | 수동/가상 코드/앱 통합 표시 | 실제 증거를 붙이거나 미실행으로 정정 |
| C1 | 변경 이유와 범위가 추적된다 | 변경 전후 표 또는 diff | 무엇이 문제였는지 같은 입력으로 재현 |
| C2 | 정상 사례를 보존하고 미실행을 밝힌다 | 변경 후 검사·미실행 목록 | 필요한 회귀 확인 또는 범위 축소 |
| D1 | 제안·검토·승인·실행이 분리된다 | 역할표와 proposal ID·version·args | 승인 대상과 실행 범위 고정 |
| D2 | 결과 불명확·중복 요청을 처리한다 | 기존 요청 조회·인수 담당자 | 확인 전 새 실행 보류 |
| E1 | 비교 기준과 원가 분모가 같다 | 동일 과제·합격 기준·고유 결과 수 | 서로 다른 배치의 숫자를 분리 |
| E2 | 준비·작성·검수·재작업을 모두 포함한다 | phase별 시간, API·도구비 | 빠진 시간·비용 보완, 중복 제거 |
| E3 | 중단·복구·재개·인계가 가능하다 | 운영표, 마지막 정상 결과, 대기 요청 | 책임자와 재개 검증 항목 지정 |
| E4 | 다음 변경을 증거로 비교한다 | 2주 기록·다음 실험 한 가지 | 완료를 꾸미지 말고 다음 확인일 기록 |

실제 데이터의 증거 위치는 승인된 저장 위치를 가리키면 됩니다. 개인정보나 비밀 값을 검토 보고서에 다시 복사할 필요는 없습니다. 가상 자료는 가상이라고 표시하고 실제 고객 처리 건수에 합치지 않습니다.

## 다섯 권별 제출물과 최소 인수 예시

### 1권: 검수된 업무 지시서와 문안

- 제출물: 원본 목록, 사실 대조표, 초안, 수정본, 확인할 질문.
- 충족 예: 원문 35,000원을 안내문·FAQ 양쪽에 반영하고 원문에 없는 신청 링크는 만들지 않음.
- 보완 예: 문장은 자연스럽지만 “마지막 두 자리”의 원본이 없음.
- 질문: “이 문장에서 어느 사실이 바뀌면 어떤 결과물까지 다시 확인해야 하나요?”

### 2권: 요구사항과 상태별 결과

- 제출물: 최소 입력, 다섯 기본 상태 사례, 사용자 안내와 다음 행동.
- 충족 예: `remaining_sessions=null`은 `needs_information`, 확인된 0은 `blocked`; 정상도 예약 전이라고 안내.
- 보완 예: 수동으로 답을 적어놓고 실제 앱 테스트 통과라고 기록함.
- 질문: “같은 blocked여도 0회와 시간 충돌의 다음 행동이 어떻게 다른가요?”

### 4권: 변경을 설명할 증거

- 제출물: 변경 전 재현, 변경 내역, 변경 후 확인, 미실행 목록.
- 충족 예: 문안 과제는 원문 대조, 코드 과제는 해당 코드의 검사 결과를 제출. 변경 없음도 근거가 있으면 허용.
- 보완 예: 실제 명령을 실행하지 않고 종료코드 0을 입력함; 또는 정답 CSV를 바꾸고 제품 결함을 수정했다고 주장함.
- 질문: “검사가 성공했지만 아직 검증하지 않은 것은 무엇인가요?”

### 3권: 검토와 실행의 인계 계획

- 제출물: 역할표, 고정된 제안 버전·대상·인자, 승인 경계, 결과 미확정 처리.
- 충족 예: 승인 없는 제안은 멈추고, 응답 유실은 기존 요청 ID로 조회하도록 설계함.
- 보완 예: 오래된 승인으로 새 대상에 발송하거나, 도구 응답이 없다는 이유로 새 요청을 보냄.
- 질문: “이 승인으로 허용되는 정확한 행동은 무엇이며, 어떤 변경이면 새 검토가 필요한가요?”

### 5권: 비용·운영판·관리자 한 장

- 제출물: 동일 기준의 비용표, 중단·복구·재개 기준, 관리자 결정서.
- 충족 예: 실패한 결과 비용도 포함하고, 유효 결과만 분모에 세며, 합성 시간과 실측을 구분함.
- 보완 예: 토큰 비용만 비교하거나, 다른 평가 사례 수를 원가 분모로 사용함.
- 질문: “검수자가 하루 더 적게 일할 수 있다면 무엇이 밀리고 언제 멈춰야 하나요?”

## 검토 자리에서 실제로 할 순서

1. 작성자가 과제 카드만 보고 범위와 결과물을 설명합니다. 설명이 달라지면 범위를 먼저 수정합니다.
2. 검토자는 결과물의 사실 하나를 골라 원본까지 따라갑니다. 찾을 수 없으면 문장 표현보다 근거 연결을 먼저 고칩니다.
3. 정상과 실패 사례를 하나씩 확인합니다. 실제 결과가 없으면 증거 유형을 미실행 또는 수동 답안으로 바로잡습니다.
4. 변경 하나를 골라 유지해야 할 규칙이 보존됐는지 확인합니다.
5. 비용표의 한 행을 직접 재계산합니다. 분모와 시간 단계가 겹치지 않는지 봅니다.
6. “담당자가 내일 부재중”이라고 가정하고 다음 사람이 중단 이유와 재개 조건을 찾게 합니다.
7. 합의되지 않은 항목만 보완 요청으로 남기고 담당자·기한·다음 검토일을 확정합니다.

실제 외부 작업을 실행하면서 확인하는 절차가 아닙니다. 문서에서 설명할 수 없는 권한·중복·복구 문제는 구현과 테스트 과제로 분리합니다.

## 인수 결정 양식

```text
프로젝트 / 검토한 버전:
검토 범위: 문서 / 가상 코드 / 실제 통합 중 해당 범위
검토자 / 검토 시각:
항목별 판정: [A1 충족 — 증거 위치] 형식으로 기록
중요 누락·실패:
보완 담당자 / 기한:
해당 없음 항목과 범위상 이유:
미실행 검사:
결정: ready_for_review / 보완 후 재검토 / 보류
결정 이유:
다음 검토일:
외부 실행 승인: 별도 / 이번 범위에 없음
```

`ready_for_review`의 자동 표시가 나와도 위 인수 결정을 생략하지 않습니다. 반대로 문안 검토만 필요한 과제에 불필요한 앱 구현을 더해 분량을 늘리지 않습니다. 업무에 필요한 증거가 충분한지가 기준입니다.
