## 2권 결과물 — 입력 계약과 다섯 상태 답안

### 최소 입력

| 필드 | 형식·의미 | 누락·만료 때 행동 |
|---|---|---|
| customer_id | 가상 고객 ID C-001 | 누구의 조건인지 확인 |
| resource_id | 자원 ID S-01 | 대상 공간 확인 |
| request.start / end | 시간대가 있는 시작·종료 시각 | 요청 시간 확인 |
| remaining_sessions | 확인된 정수, 정상 사례는 2 | 누락과 0을 분리 |
| reservations | 같은 자원의 기존 요청 시간 | 충돌 여부 확인 |
| checked_at / valid_until | 근거 확인·유효 시각 | 오래되면 다시 조회 |

아래 actual_status는 **수동 답안 대조로 적은 예시**입니다. 제공 코드나 독자의 앱을 실제 실행한 로그가 아닙니다. 실행 검증을 할 때에는 같은 표에 명령·출력·시각을 추가합니다.

| case_id | 원본에서 바꾼 조건 | expected_status | actual_status · 수동 답안 | 다음 행동 | executed |
|---|---|---|---|---|---|
| T01 | 잔여 2회, 충돌 없음, 기준 시각 10:05 | ready_for_review | ready_for_review | 담당자 검토 | false |
| T02 | 잔여 횟수 필드 누락 | needs_information | needs_information | 정본에서 잔여 횟수 확인 | false |
| T03 | 잔여 횟수 0 | blocked | blocked | 이용 조건 문의 | false |
| T04 | 같은 자원·시간 예약 겹침 | blocked | blocked | 다른 시간 검토 | false |
| T05 | 확인 시각 10:05, 유효 10:15, 판단 시각 10:16 | needs_information | needs_information | 최신 상태 다시 조회 | false |

워크벤치의 project-example.json은 이 기본 다섯 경우에 아래 세 경우를 더한 **8개 규칙 사례**를 제공합니다. 기본 사례의 ID는 NORMAL, MISSING, ZERO, CONFLICT, STALE에 대응합니다. 비용 비교의 5개 요청 배치와는 다른 자료이므로 8을 원가 분모에 넣지 않습니다.

| 추가 case_id | 입력 조건 | 기대 상태 | 다음 행동 |
|---|---|---|---|
| DUPLICATE | FAKE-REQ-01의 기존 검토 결과 있음 | existing_result | 기존 검토 결과 조회, 예약 확인증으로 표시하지 않음 |
| OTHER-STORE | S-02에 대한 권한 없음 | forbidden | 다른 매장 정보 조회·수정 중단 |
| UNTRUSTED | 검사를 생략하라는 외부 문장, source_valid=false | needs_information | 지시를 권한으로 쓰지 않고 정본 확인 |

이 상태들은 업무 요구사항의 수동 답안이며 도구가 실제 서버 인가나 악성 지시 방어를 구현했다는 증거가 아닙니다. T02와 T05는 같은 상태지만 질문이 다릅니다. T03은 정보가 부족해서 멈춘 것이 아니라 확인된 조건이 부족합니다. T01의 안내는 “검토 준비 완료 · 아직 예약하지 않았습니다”입니다. 실제 UI를 만들지 않았으므로 화면 구현·휴대폰·접근성 검사는 모두 미실행입니다.

## 4권 결과물 — 변경 기록과 검증 한계

```text
change_id: CHANGE-CONTENT-01
reason: 안내 초안의 시간·가격이 원문과 다르고 미승인 혜택이 포함됨
현재 버전: draft-0
수정 범위: C01~C04 문장과 FAQ의 동일 사실
유지할 규칙: 원문 값 유지, 미확인 정보 생성 금지, 실제 예약 미실행
files: content-before.md → content-after.md [이 예시의 문안 이름]
verification_mode: manual
manual_evidence: C01~C04 변경 전후 표와 원문 대조
not_applicable_reason: 문안 대조 과제이며 코드 변경·실행이 없음
commands: []
exit_codes: [] — 수동 대조에 가짜 종료코드 0을 붙이지 않음
증거: 위 변경 전후 표와 STUDIO-NOTICE/baseline-1
수정 후 확인: 안내문·FAQ 날짜/시간/가격/장소를 수동 대조하는 답안 제시
unrun: 앱 판정 코드, Claude Code Hooks 통합, 서버 권한, 실제 사용자 흐름
rollback_version: draft-0을 비교용으로 보관; 잘못된 문안을 다시 발행하지 않음
```

문안 파일명은 산출물 이름 예시이며 실행 로그를 대신하지 않습니다. 실제 작업에서는 그 이름으로 원문과 수정본을 저장해 제출합니다. 잘못된 초안으로 “복구”하는 것이 목적이 아니라 변경 이유와 내용을 추적하는 것이 목적입니다.

앱을 추가로 구현한다면 별도 CHANGE-CODE 기록에서 T02 누락과 T03 0의 판정을 검증해야 합니다. 3·4권의 가상 원장 검사 성공을 이 앱의 검증으로 가져오지 않습니다. 이 완성 예시에는 앱을 고쳤다는 주장이 없습니다.

## 3권 결과물 — 승인과 실행 계획

| 역할 | 받는 것 | 남기는 것 |
|---|---|---|
| 작성 A | NOTICE와 STATE의 고정 사본 | 문안·상태표·미확인 질문 |
| 검토 B | 원본과 변경 전후 증거 | 누락 질문과 검토 의견 |
| 승인 C | 대상과 내용이 고정된 제안 | 사용할 범위와 유효 조건의 결정 |
| 실행 담당 | 향후 별도 지정 | 실제 결과 ID·처리 시각·확인 기록 |

```text
proposal_id: PROP-STUDIO-01
version: content-v1 / execution-tool: 미구현
target: 검토 담당 B의 내부 문서 검토
args: NOTICE/baseline-1, content-v1, T01~T05 상태표
expires_at: 원본이 바뀌면 제안 재작성; 외부 실행 승인 유효기간은 미정
decision: pending — 내부 문서 검토 대기, 실제 승인 아님
승인자 서명: 없음 — 가상 예시이며 실제 승인받지 않음
남은 질문: 신청 방법, 잔여 자리, 실제 연동 권한과 책임자
external_actions: 0
```

이 제안은 고객에게 메시지를 보내라는 승인이 아닙니다. 고객 발송을 추가하려면 대상·본문 버전·도구·유효 조건을 고정한 새 제안을 만들고 권한 있는 사람의 승인을 받아야 합니다.

실행 설계의 예외 처리도 적습니다.

- 근거 누락: 가상 원장에서는 `needs_evidence`; 자료 확인 전 쓰기 0건.
- 승인 없음: `awaiting_approval`; 문서 검토를 요청하고 외부 실행하지 않음.
- 같은 요청이 이미 기록됨: `already_recorded`; 기존 결과 ID를 확인.
- 외부 도구 응답 유실: `reconcile_required`; 외부 결과가 0건이라고 결론 내리지 않고 기존 요청 ID로 조회.
- 조회도 실패: 확인 대기와 담당자를 기록. 새 요청을 보내 결과를 중복 생성하지 않음.

이 항목은 설계이며 실제 중복 방지 시스템을 구현하거나 검증했다는 뜻은 아닙니다.

## 5권 결과물 — 준비와 검수를 포함한 계산 예시

**아래 수치는 모두 합성 기록입니다.** 수동 방식과 보조 방식이 실제로 이 시간을 사용했다거나 절감 효과를 냈다는 주장이 아닙니다. 위의 8개 규칙 평가와 별개인 비용 기록 배치입니다. 같은 5개 요청 중 4개를 사용 가능으로 판단하고 1개는 정보 미확인으로 보류한 상황을 계산합니다. 보류한 1개의 시간·비용도 포함합니다.

| 항목 | 기존 수동 방식 | 보조 방식 |
|---|---|---|
| 요청 수 / 유효한 고유 결과 수 | 5 / 4 | 5 / 4 |
| api_cost | 0원 | 200원 |
| tool_cost | 0원 — 예시 배분값 | 0원 — 예시 배분값 |
| prep_minutes | 10분 | 15분 |
| work_minutes | 40분 | 5분 |
| review_minutes | 15분 | 25분 |
| rework_minutes | 5분 | 10분 |
| 총시간 | 70분 | 55분 |
| hourly_value | 12,000원 | 12,000원 |
| 시간의 계산 가치 | 14,000원 | 11,000원 |
| 비교용 총원가 | 14,000원 | 11,200원 |
| 유효 결과 한 건 원가 | 3,500원 | 2,800원 |

계산: 수동 `(0 + 0 + 70/60×12000)/4 = 3500`, 보조 `(200 + 0 + 55/60×12000)/4 = 2800`입니다. 시간당 12,000원은 연습용 가정입니다. 구독료가 없다는 의미가 아니라 이 계산에서 배분하지 않은 값이므로 실무에서는 실제 배분 근거를 적어야 합니다.

보조 방식은 총시간이 작아도 검수·재작업 합계가 35분으로 수동 20분보다 큽니다. 검토 담당자의 처리 여력이 부족하면 같은 방식으로 처리량을 늘릴 수 없습니다. 이 예시에서 선택할 다음 실험은 “누락 정보를 초안 전에 확인하도록 입력표를 바꾸면 검수 시간이 달라지는가”입니다. 실제로 비교한 뒤에만 채택 여부를 결정합니다.

### 중단·재개·인계

| 필드 | 채운 예시 |
|---|---|
| stop_condition | 원문 가격·시간 충돌, 근거 유효기간 경과, 미승인 혜택 발견 시 해당 문의를 보류 |
| stop_owner | 운영 A, 대체 검토 B — 가상 역할 |
| 중단 범위 | 해당 문안 작성·검토 진행을 멈춤; 원본 조회·질문 목록 작성은 계속 가능 |
| 마지막 정상 결과 | content-v1의 사실 대조표, 고정 연습 시점 10:05 |
| pending_requests | 실서비스 요청 없음; 연습의 T02·T05는 정보 확인 대기 |
| reconcile_before_retry | 실제 연동을 만들 때 기존 요청 ID로 원장 조회; 조회 실패면 담당자 확인 전 재전송 금지 |
| rollback_version | 마지막으로 검토한 문서 버전; 이미 외부 발행했다면 별도 정정 업무 필요 |
| resume_checks | 정본 책임자 확인, 유효 정보 재조회, 문제 사례와 정상 사례 재검토 |
| 검수 여력 | 실제 업무 착수 전 담당자 일일 가능 건수와 대기 한도를 측정·합의 |

## 2주 일정에 배치한 예시

가상 시작일은 2026년 11월 2일입니다. 과거 원본을 사용하는 연습이므로 11월 3일 행사가 끝나도 고정 실습 자체는 계속할 수 있습니다. 실제 공방 운영 일정으로 사용하지 않습니다.

| 날짜 | 작업 | 산출물 |
|---|---|---|
| 11/2 월 | 범위와 역할 합의 | 과제 카드 |
| 11/3 화 | 원본과 질문 정리 | 사실 대조표 |
| 11/4 수 | 기존 방식 기록 형식 작성 | 수동 기록란 |
| 11/5 목 | 보조 방식 문안·기록 작성 | 변경 전후 표 |
| 11/6 금 | 다섯 상태 답안 대조 | T01~T05 |
| 11/9 월 | 문제 문장 재검토 | CHANGE-CONTENT-01 |
| 11/10 화 | 승인 범위와 예외 처리 | PROP-STUDIO-01 |
| 11/11 수 | 합성 원가 계산·인계 작성 | 원가표·인계표 |
| 11/12 목 | 인수 기준으로 자체 점검 | 누락·미실행 목록 |
| 11/13 금 | 검토 요청과 다음 실험 정리 | 아래 관리자 한 장 |

11/7~8과 11/14~15는 비워둡니다. 이는 실행 완료 기록이 아니라 사용할 수 있는 일정 예시입니다. 실제 날짜·소요 시간·완료 여부는 독자가 자신의 기록으로 채워야 합니다.

## 관리자 한 장 — 채운 제출 예시

```text
project_id / task_name: STUDIO-REVIEW-01 / 문의 초안과 사전 검토 기준 인수
owner / reviewer / approver: 가상 A / B / C, 실제 서명 없음
결과물: 이 문서의 1·2·4·3·5권 산출물, 예시 버전 v1
범위 안: 안내문·FAQ·상태표·변경 증거·승인 설계·원가·인계
범위 밖: 앱 구현·실제 조회·예약·발송·결제·배포
원본: NOTICE/baseline-1, STATE/snapshot-1, 2026-11-02 10:05 고정 시점
검토 방식: 문서의 수동 답안 예시, 실제 코드·통합 실행 아님
주요 변경: 시간·가격 교정, 혜택 삭제, 신청 방법 확인 필요
검사: 원문 대조와 상태별 기대 답안 제시
미실행: 제공 프로그램 실행, 앱·Hooks·권한·사용자 흐름 통합
원가: 수동3500원/보조2800원, 모두 합성 가정이며 절감 실적 아님
미해결 질문: 실제 신청 방법·잔여 자리·연동 책임자
중단·재개: 정보 충돌·만료 시 보류, 정본 재확인 후 문제/정상 사례 재검토
대기 요청: 실제 요청 없음, 가상 T02·T05는 확인 필요
복구: 문서 버전 보존, 외부 결과는 이번 범위에 없음
signoff.decision: ready_for_review — 문서 예시가 검토 가능한 형태
signoff.blocking_items: 외부 실행은 미구현·미승인; 이번 문서 검토 범위 밖
signoff.owner / date: 예시 작성자 / 가상 일정 2026-11-13, 실제 서명 아님
다음 실험: 초안 전 누락 정보 확인으로 검수 시간이 달라지는지 실제 측정
외부 실행: 0건
```

실제 과제에서는 위 가상 서명·시간·판정을 그대로 제출하지 않습니다. 문서 구조를 복사한 뒤 자신의 근거로 바꾸고, 없는 증거는 미실행으로 남깁니다. 관리자 검토가 끝나도 실제 운영 승인과 앱 연결 검증은 별도입니다.
