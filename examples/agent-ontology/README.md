# AI 바이블: 온톨로지와 에이전트 검토 실습

2026-10-25 전권 보강의 공통 예제입니다. 모든 고객·자원·예약·시각은 가상 데이터입니다. Python 표준 라이브러리만 사용하며 API 키와 별도 패키지가 필요하지 않습니다.

세 파일을 같은 폴더에 내려받은 뒤 그 폴더에서 실행합니다.

```sh
python ontology_lab.py
python -m unittest -v test_ontology_lab.py
```

macOS/Linux에서 `python` 명령이 없으면 `python3`를 사용합니다.

기본 출력은 `ready_for_review`, `executed: false`입니다. 코드는 읽기와 검토만 합니다. 예약 생성, 회차 차감, 알림 발송, 결제, 승인 처리, 데이터베이스 접속은 구현하지 않았습니다. `approved: true`를 요청에 넣어도 실행하지 않습니다.

## 바꿔보며 익히기

1. `remaining_sessions`를 지워봅니다: `needs_information`.
2. 0으로 바꿉니다: `blocked`. 누락과 0의 차이입니다.
3. 기존 예약을 14:30에 시작하게 바꿉니다: 시간 겹침으로 `blocked`.
4. `availability_coverage.complete`를 false로 바꿉니다: 빈 예약 목록만으로 빈 시간을 단정하지 않습니다.
5. 정보 유효 시각을 10:04로 바꿉니다: 샘플 현재 시각 10:05보다 과거라 다시 조회해야 합니다.

## 범위와 실서비스 확장

공통 개념·고유 ID·관계를 정리한 작은 애플리케이션 설계와 명시적 업무 규칙을 설명하는 예제입니다. RDF/OWL 추론 엔진이나 그래프 데이터베이스를 구현한 것이 아닙니다. 유효 기간 15분은 이 예제의 학습용 설정이며 업종 표준이 아닙니다.

실서비스는 인증된 사용자·매장 범위, 서버의 권한·승인 검증, 원본 실시간 재조회, 트랜잭션, 중복 요청 방지 저장소와 감사 로그가 필요합니다. 동시 예약의 마지막 충돌은 데이터베이스의 트랜잭션/제약에서 막아야 합니다. 이 읽기 전용 예제로 그 문제까지 해결됐다고 간주하면 안 됩니다.
