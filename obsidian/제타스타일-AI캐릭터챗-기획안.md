# AI 캐릭터챗 서비스 기획안 — 제타(Zeta) 벤치마킹 + 오픈소스 스택

> 목표: 월 매출 1억원. 제타(스캐터랩)와 정면 승부하지 않고, 좁은 타겟에서 현실적으로 도달 가능한 경로를 설계.

## 1. 벤치마킹 — 제타(Zeta)
- 운영사: 스캐터랩(이루다 개발사). 2024년 4월 정식 오픈, 국내 최초 "AI와 실시간으로 스토리 창작" 플랫폼 표방.
- 2026년 2월 기준 국내 AI 챗봇 앱 **이용시간 1위**, 이용자 수 ChatGPT 다음 2위. 가입자 약 600만.
- 벤처캐피탈 투자 약 500억원 확보.
- 자체 sLLM **핑퐁-1(PingPong-1)**: 카카오톡 대화 100억 건 학습, 감정·소셜 상호작용 특화. 한국어 자연어 이해 강점.
- B2B 솔루션 **핑퐁 스튜디오**: 파트너사가 AI 지식 없이도 자체 캐릭터를 만들 수 있는 노코드 빌더 제공 — 이 모델이 이번 기획의 B2B 트랙 벤치마크.
- 최근 "캐릭터 1명과의 대화"에서 "여러 등장인물+세계관을 포함한 콘텐츠 단위(플롯)" 스토리 플랫폼으로 확장 중 → 범용 캐릭터챗보다 스토리 완성도 경쟁으로 이동하는 신호.

## 2. 왜 범용 시장으로 못 들어가는가
같은 시장(범용 로맨스/판타지 롤플레잉)에서 정면 승부 시 필요한 규모:
- 월 구독 9,900원, 유료전환율 5% 가정 → 월 1억 매출에 필요한 MAU 약 **20만 명**
- 오픈소스 스택 기반 인디/소규모 팀이 초기에 도달할 수 있는 규모가 아님. 제타(가입자 600만·투자 500억) 대비 자본·데이터(카카오톡 100억건 학습)에서 압도적 열위.

**결론: 타겟을 좁혀서 제타가 못 채우는 자리를 공략해야 월 1억이 현실적.**

## 3. 타겟 — 2트랙 전략

### 트랙 A (1차, 현금흐름) — B2B 화이트라벨 SaaS
- 타겟: 자체 캐릭터 IP는 있지만 AI 챗 기능을 직접 개발할 여력이 없는 **중소 웹툰/웹소설 플랫폼, 오토메(여성향 연애 시뮬레이션) 게임 개발사, 인디 게임사**
- 제공 가치: 오픈소스 스택(Agnaistic/SillyTavern 기반) + 오픈웨이트 모델(Qwen2.5, HyperCLOVA X API 등)로 원가를 낮춰, 핑퐁 스튜디오가 커버하지 않는 중소형 고객사를 공략
- 수익 구조: 계약단가 월 300만~1,000만원 × 고객사 10~30곳 = **월 1억원**
- 세일즈 사이클은 길지만 "유저 수백만 명" 없이도 도달 가능한 경로

### 트랙 B (2차, 브랜드·데이터 축적) — 니치 B2C: 여성향 로맨스판타지/BL
- 타겟 페르소나: 20~30대 여성, 카카오페이지·리디북스·문피아 등에서 로맨스판타지/BL 웹소설·웹툰에 **이미 유료 결제 경험이 있는** 독자 (결제 전환 장벽이 낮음)
- 페인포인트: 회귀·빙의·계약결혼·후회공 같은 클리셰를 좋아하지만, 기존 웹소설은 스토리가 고정되어 있어 "내가 원하는 전개"로 못 감
- 차별화: 제타는 범용 캐릭터 생성의 자유도에 강점이 있지만 장르 전문성·시나리오 완성도는 약함 → **로판/BL 전문 작가와 협업한 고품질 캐릭터카드·세계관을 큐레이션**해 승부
- 수익 구조: 월 29,900원(범용 서비스보다 3배 높은 ARPPU, 니치 커뮤니티는 이탈 적음) × 유료전환율 10% 가정 → 필요 MAU 약 **3.3만 명**
- 국내 로판/BL 웹소설 독자 총량은 수십만~백만 단위로 존재 → 3.3만 MAU는 현실적 목표

## 4. 기술 아키텍처 — 오픈소스 스택

| 레이어 | 후보 | 비고 |
|---|---|---|
| 프론트엔드(채팅 UI) | **SillyTavern** | 가장 성숙, 캐릭터카드/월드북/확장 생태계 최대. 참고용 |
| | **Agnaistic (agnai)** | Node+TypeScript, 멀티유저 서버형 구조 — SaaS로 확장할 원형에 더 가까움. [github.com/agnaistic/agnai](https://github.com/agnaistic/agnai) |
| | **RisuAI** | 모바일 앱까지 패키징, 크로스플랫폼 |
| 캐릭터 데이터 포맷 | **chara_card_v2 / v3 spec** | PNG tEXt 청크에 JSON 메타데이터 내장(name/description/personality/scenario/first_mes/mes_example). 업계 사실상 표준. [spec 저장소](https://github.com/malfoyslastname/character-card-spec-v2) |
| LLM 백엔드 | 한국어 특화: HyperCLOVA X(네이버), Kanana(카카오), VARCO(NCsoft, 게임·대사 특화) / 오픈웨이트: Qwen2.5(한국어 자연스러움 우수), Llama 3.3 70B | 자체 파인튜닝 시 LoRA로 로판/BL 장르 대사 데이터셋 학습 |
| 메모리 | Lorebook(세계관 고정정보) + Vector DB RAG(장기기억) | 원칙: "사실은 RAG, 성격은 카드에" — 섞으면 캐릭터가 납작해짐 |
| 인프라 | Docker, Postgres/Mongo | Agnaistic은 DB 없이 익명모드 구동도 가능(MVP 검증용) |

## 5. 리스크 — 반드시 설계 단계부터 반영
- **AI 기본법 2026.1.22 시행**: AI 생성물 표기 의무화(문구/워터마크/메타데이터 중 택1) — 채팅 UI에 명시적 고지 필요
- **미성년자 보호**: 국내 캐릭터챗 가입자 약 30%가 10대로 추정, 생년월일만 입력하면 가입되는 구조가 최근 국감·시사프로에서 지적됨. 사후 대응 시 서비스 존폐 리스크 → MVP부터 연령확인 + 선정적 대화 필터링 내장 필요
- B2B 트랙은 이 리스크를 파트너사와 분산할 수 있다는 부수적 장점도 있음(콘텐츠 등급·정책은 파트너사 플랫폼 기준을 따름)
